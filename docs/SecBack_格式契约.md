# SecBack 格式契约

以 core/src/format.rs、vault.rs、crypto.rs 和 tests/vectors.rs 为准，更新：2026-11-26。整数均为小端，字符串为 u32 UTF-8 字节长度后接原始内容，文件由明文头和 AES-256-GCM 密文负载组成。

## 文件头

| 偏移 | 长度 | 字段 |
|---:|---:|---|
| 0 | 8 | magic：53 45 43 42 4B 00 01 00 |
| 8 | 2 | version：1 或 2 |
| 10 | 2 | flags；v1 输出为 0，v2 bit0 表示恢复槽 |
| 12 | 4 | PBKDF2-HMAC-SHA256 iterations，新库 200000，读取上限 2000000 |
| 16 | 16 | 主密码 salt |
| 32 | 12 | payload nonce |
| 44 | 4 | 保留，输出为 0 |
| 48 | 8 | 密文负载字节数，包含 16 字节 tag |
| 56 | 8 | 保留，输出为 0 |
| 64 | 12 | v2 主密码 wrap nonce |
| 76 | 4 | v2 保留 |
| 80 | 48 | v2 wrapped DEK：32 字节密文 + 16 字节 tag |
| 128 | 16 | v2 恢复 salt |
| 144 | 12 | v2 恢复 wrap nonce |
| 156 | 48 | v2 recovery wrapped DEK |
| 204 | 52 | v2 保留 |

v1 头共 64 字节，口令派生 32 字节密钥直接加密正文。v2 头共 256 字节，随机 32 字节 DEK 加密正文；主密码派生 KEK 包装 DEK，恢复码另派生 KEK 包装同一 DEK。AES-GCM 使用 12 字节 nonce，输出密文后附 16 字节 tag，当前不带额外 AAD。

v2 恢复码为 20 随机字节，编码为 32 字符 Crockford Base32。KDF 输入为规范化后的 32 字符编码（实际调用见 vault.rs），不是显示用短横分组。

文件实际长度必须等于头长度加 payload_size，使用 checked 算术；不接受截断或额外字节。新库保持 v1，主动设置恢复码时升级 v2。当前改密仍整文件保存与原子替换，不是仅头部补丁。

## 解密后负载

1. u32 项目数量。
2. 每项目依次为：id[16]、name 字符串、remark 字符串、u64 created_utc、u64 modified_utc、u32 slots_n（必须为 3）。
3. 每个槽依次为 user、pass、remark 三个字符串，共三槽，不压缩空槽。
4. 时间戳为从 1601-01-01 起的 100ns FILETIME。
5. 读完必须恰好到负载末尾。UTF-8 错误、长度越界、账户槽数错误均拒绝。

单项目最少 80 字节。最多 100000 项、单字段 1 MiB、明文负载 64 MiB；写盘先用 try_serialize 验证相同上限，避免写出自身拒绝的文件。载荷密文上限为 64 MiB + 16，文件上限为 64 MiB + 272。

## 保存及兼容

保存通过候选 Store 完成，成功后才替换内存。每次使用新 nonce、唯一 create_new 临时文件、文件同步和重命名。保存前锁定旁路锁文件并比对已加载文件哈希；变更则报冲突。替换前轮转三份加密备份。可用性与耐久保证边界见 能力与限制.md。

v1 的 10 项固定向量测试保持逐字节兼容；v2、恢复、事务失败和限制由核心单测覆盖。C++ 参考实现冻结于 v1，不能泛称所有版本跨实现互通。任何布局变更都需新增版本、迁移规则和测试向量。
