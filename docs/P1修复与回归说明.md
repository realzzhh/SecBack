与 P1 紧密相关的一并处理：快照更新清理详情密码缓存；详情 reveal 请求拒收过期消息；恢复流程在宿主限制业务命令；耗时 IPC 放入工作线程，宿主操作串行化以避免锁定与提交交错。修正两项测试的硬编码磁盘路径，统一使用临时目录。

## 回归方式

1. 核心：`cargo test --manifest-path core/Cargo.toml --offline`。新增事务写入故障矩阵及满副本导入回归。
2. 前端语法：`node --check src/app.js`。
3. 编译后界面：以独立 SECBACK_VAULT 和 CDP 端口启动桌面 debug，再运行 `node tests/p1-ui.mjs`。脚本用虚构数据拦截协议，覆盖稀疏槽位、删除前移、读回竞态、删除确认及 393×851 布局。只用于专用测试窗口。
4. 实际宿主：隔离密库中验证保存、退出重登、账户前移密码；用同名 `.tmp` 目录制造写盘失败，确认磁盘不变、快照不变、草稿保留、恢复后可重试；锁定检查全部敏感 DOM。
5. Android：使用原发布证书覆盖安装，验证表单和系统保存选择器；导出备份拉回本机后由核心库读取验证。不卸载、不清空现有调试密库。

改前端后仍须更新 `src-tauri/src/lib.rs` 修改时间再构建，以确保资源重新嵌入。原有移动编辑弹层 head → foot → body 顺序和顶部固定操作栏保持不变。

## 使用边界

- 备份保存的是已成功落盘的密文，不包含未保存的编辑草稿。使用备份导出时有效的主密码或恢复码读取。
- Android 外部密库导入仍是独立待办；本轮提供导出，可由电脑版读入，不宣称手机端恢复闭环已完成。
- 前端清空 DOM 和 JS 引用不能保证 JavaScript 垃圾回收区物理归零。Rust 的显式擦除也不等于完成进程内存取证级别的证明。
- P2/P3 中剪贴板、备份系统策略、签名配置、资源限制及其他项目未在本轮全面整改。
