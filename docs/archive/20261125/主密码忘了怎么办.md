# 主密码忘了怎么办

日期：2026-11-05
状态：**方案 B 已实施**（2026-11-06）。

---

## 一、结论

**已支持恢复码。** 设了恢复码之后，忘了主密码可以用它打开。

没设恢复码的库仍然是「忘了就是丢了」——这是默认状态，需要你主动开启。

---

不是 bug，是设计的结果。文件头里只有这些：

| 字段 | 内容 | 能帮上忙吗 |
|---|---|---|
| magic | `SECBK\0\1\0` | 不能 |
| version | 1 | 不能 |
| iterations | 200000 | 不能 |
| salt | 16 字节随机 | 不能（它的作用恰恰是让每次派生都不同） |
| nonce | 12 字节随机 | 不能 |
| payloadSize | 长度 | 不能 |

密钥是 `PBKDF2(密码, salt, 20万轮)` **现场算出来的**，不存盘、不缓存、不派生第二份。
密码错了，算出来的就是一串无意义的数字，AES-GCM 的 tag 校验直接失败。

**代码里没有万能密码。** 里唯一出现 `旧默认口令` 的地方是"判断用户是不是在用默认密码"，
用来在界面上提醒——它不会绕过任何校验。

所以这件事只能**提前防**，不能事后救。

---

## 二、为什么"想个办法找回来"在技术上不成立

想找回来，文件里必须留下某种"能和密码对上"的痕迹。而任何这种痕迹都是攻击面：

- **存密码哈希** → 哈希就是离线爆破的靶子，攻击者不再需要猜，直接对着哈希算
- **存加密的密码副本** → 那串东西的钥匙又在哪？无限递归
- **留一个"管理员通道"** → 通道本身就是新的入口

密码本的全部价值就在于"没有密码，天王老子也进不去"。所以这类工具一律
选择：**宁可让你丢数据，也不给任何人（包括作者）留后门**。

那能不能既保留强度、又留一条你能用的通道？能——**恢复密钥**，但代价不小（见下）。

---

## 三、三条可选出路

### 方案 A：密码提示（最轻）

设密码时可选填一句提示，比如"公司名+入职年份"，明文存在密库旁边的小文件里。

- **能帮上多少**：只能帮着回忆，忘了就是忘了
- **代价**：提示是明文的，能拿到文件的人也能看到。**别写成"密码是某某+123"这种**
- **改动量**：半天，密库格式不变，C++ 版照样读
- **我的看法**：聊胜于无。真忘了多半想不起来，但"提示"能帮你在试的时候缩小范围

### 方案 B：恢复密钥（最有效，但要改格式）

设密码时同时生成一串 **128 位随机码**（形如 `7K3M-9XQ2-VB4N-...`），
用它单独包一份"数据密钥"。两条路都能开门：

```
密码     ──PBKDF2──> KEK₁ ─┐
                          ├─> 解密 DEK ─> 解密内容
恢复码   ──PBKDF2──> KEK₂ ─┘
```

这顺带解决另一个问题：**改密码只需重新加密 32 字节的 DEK，不用重写整个库**
（现在是全库重写，库大了会卡一下）。

- **能帮上多少**：真能救。这是 1Password / Bitwarden 的标准做法
- **代价**：格式要升到 v2，**C++ 版从此读不了 Rust 写的库**（Rust 能向下兼容读 v1）
- **改动量**：2~3 天。核心是引入随机的 DEK，改成"信封加密"
- **关键前提**：恢复码必须**打印出来或抄在纸上**，放在和电脑分开的地方。
  存在电脑里等于没设——电脑丢了/坏了，两个一起没

### 方案 C：明文应急出口（最土，但真管用）

一键把全部账号密码导出成明文文本/CSV，自己打印锁抽屉。

- **能帮上多少**：100%。忘不忘密码都无所谓，纸上写着
- **代价**：**最高**。这张纸一旦被看到，密码本等于没加密
- **改动量**：半天，格式不变
- **我的看法**：只在"这些密码丢了会出大事"的场合考虑，而且导出后要立刻离线

### 对比

| | 能不能救 | 安全代价 | 改动量 | 与 C++ 版兼容 |
|---|---|---|---|---|
| A 密码提示 | 弱 | 泄漏线索 | 小 | ✅ 不变 |
| B 恢复密钥 | **强** | 多一条通道 | 中 | ❌ 断交 |
| C 明文导出 | **强** | 高 | 小 | ✅ 不变 |
| D 双密码（两个密码都能开） | 强 | 两个都得保管 | 中 | ❌ 断交 |

> **注意一个常见误解**：把 `sec.properties` 备份到网盘**不能**防忘密码——
> 备份的还是加密的，忘了密码照样打不开。备份能防的是"文件损坏/误删"，是另一回事。

## 四、我的建议

**立刻做（今天就能加）**：方案 A。成本极低，格式不动。

**建议做**：方案 B。这是唯一"既不降低加密强度、又真能救命"的设计。
但要接受 v2 与 C++ 版断交——考虑到 C++ 版已经冻结为参考实现、手机端本来就是新代码，
这个代价其实可以接受。

**不推荐**：方案 C 作为常规功能。它把整个安全模型拉回到"一张纸"的水平。

如果只能选一个：**选 B**。A 是安慰剂，C 是赌运气。

## 五、如果已经忘了——抢救清单

按成功率排序：

**1. 别的设备上还有没有一份？**
手机、旧笔记本、U 盘、网盘的备份目录。那一份是用**当时的密码**加密的。
如果能打开，把内容导出来重新建库即可。

**2. 翻旧版本**
Windows 的「卷影副本 / 以前的版本」、文件历史、OneDrive 的版本历史。
旧版本可能对应**更早的密码**——如果你改过密码，这一条特别值得试。

**3. 看目录里有没有 `.tmp` 残留**
写盘是 `.tmp` + 原子重命名。如果某次写入中途中断过，目录里可能留下
`sec.properties.tmp`，那是当时的完整内容。

**4. 系统地试变体**
如果有人帮忙，这个最实用。常见方向：

- 大小写（CapsLock 误触）
- 中文/英文输入法状态打出来的差异
- 键盘布局（Q/W、Z/Y 这类）
- 结尾少打/多打一个字符
- 上一版密码（改密码之前的）
- 你自己惯用的"基础词 + 年份/符号"组合

20 万轮 PBKDF2 在 release 版上大约每次 0.1~0.2 秒，
**一小时能试 2~3 万个候选**。所以：

- 记得大致模式（比如"公司名+年份+符号"）→ 组合数几千到几万，**可行**
- 完全随机 12 位 → 不可行，别浪费时间

需要的话我可以写个批量试密码的小工具，你把能想到的方向告诉我，我生成候选列表跑。

**5. 实在不行**
只能重建。这时候至少把这次的教训用上：新库设好之后，立刻做恢复密钥或者
把关键密码抄到纸面上。

## 六、如果决定做恢复密钥，要动什么

技术上是这些（先说清楚，免得以为改两行就行）：

1. **引入随机 DEK**：现在 `key = PBKDF2(密码)` 直接加密内容，要改成
   随机生成 32 字节 DEK，内容用 DEK 加密
2. **头扩展到 128 字节**，加一个恢复槽：`recoverySalt(16) + nonce(12) + wrappedDEK(48)`
3. **两个解包路径**：密码解开 KEK₁、恢复码解开 KEK₂，都解出同一个 DEK
4. **格式版本升到 2**，读的时候 v1 自动升级（打开旧库时问一句"要不要启用恢复密钥"）
5. **恢复码生成界面**：分组显示、可打印、强制用户抄一遍再继续
6. **C++ 版**：冻结在 v1，读不了 v2 的库

改动集中在 `core/src/format.rs`、`crypto.rs`、`vault.rs`，加上界面。

## 七、还有一件事

现在程序里认 `旧默认口令` 这个"默认密码"，是从 C++ 版继承下来的习惯。
如果你现在真的在用 `旧默认口令` 或者类似的弱密码，**那比忘密码更危险**——
这种库落到别人手里，跑几秒钟就开了。建议先把这个改掉。

## 八、实施状态（2026-11-06 已完成）

方案 B 已落地。用法：

1. 菜单 **文件 → 设置恢复码…**，输入当前主密码
2. 弹出 32 字符的恢复码（形如 `Z77M-P3DT-D6JH-…`），**抄在纸上**
3. 系统要求输入**最后 8 位**核对，确保你没抄错
4. 以后忘了主密码，在登录页点 **「主密码忘了？用恢复码打开」**，输码即可
5. 解开后**必须设新密码**才能进入——否则你改了数据一保存，库里存的还是那把忘掉的口令

### 技术实现

```
口令 ──PBKDF2(salt₁)──> KEK₁ ──┐
                              ├─> 解出 DEK ──> 解密正文
恢复码 ─PBKDF2(salt₂)──> KEK₂ ──┘
```

- 正文用随机 DEK 加密，DEK 被口令和恢复码各包一份（信封加密）
- 头从 64 字节扩到 256 字节，格式版本升到 **v2**
- 升级是**自动**的：设恢复码时，v1 库自动换成随机 DEK 并重写为 v2
- **改主密码只重新包 32 字节的 DEK，不再重写整个库**（顺带解决了库大了改密码卡一下的问题）
- 恢复码用 Crockford Base32（去掉 I/L/O/U 这四个易混字符），抄写顺序错乱、大小写混用、多打空格都能识别

### 代价（务必知道）

**v2 的库，C++ 版读不了。** 实测确认过。

没设恢复码的库仍是 v1，两边都读得了。**只有你主动设了恢复码，这个库才变成 Rust 专属。**

### 恢复码保管的三条铁律

1. **抄在纸上，和电脑分开**。存在同一个硬盘里等于没设——硬盘坏了两个一起没
2. **不要拍照存手机**。手机丢了、云同步了，等于多一个泄漏点
3. **重新生成会让旧码立即失效**。换新码之后，把旧纸销毁

### 还有个细节

恢复码生成后如果点了「稍后再说」没抄，码**已经写进密库了**但你没拿到——
这时界面上会警告一次。遇到这种情况，重新生成一组即可（旧的自然作废）。
