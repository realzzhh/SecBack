## 2. 一个关键决策：重写核心，不做 cxx 桥接

原计划是用 `cxx` crate 把现有 C++ 核心桥接进 Rust。动手时改成了 **Rust 重写**，理由只有一个：

**要上手机。**

| 方案 | 桌面 | Android | 后果 |
|---|---|---|---|
| cxx 桥接 C++ | ✅ | ❌ 要 NDK + CMake + 三套 ABI | 手机端等于再养一套 C++ 工具链 |
| Rust 重写 | ✅ | ✅ 一份代码通吃 | 多花 1~2 天 |

而且这次重写的风险被压得很低，因为**准备工作早就做好了**：
- `docs/SecBack_格式契约.md` 是完整字节规范
- `docs/format_vectors.txt` 是固定的对拍向量
- C++ 版 83 项 selfcheck 把行为边界都框死了

结果：核心 4 个文件约 900 行，加上测试一次通过，**没有出现"格式对不上"的反复调试**。

## 5. 踩到的坑（Tauri 特有）

### 5.1 事件监听是异步的，`ready` 发早了会丢消息

Tauri 的 `event.listen()` 返回 Promise。原来的写法是"注册完立刻发 ready"，
结果宿主的 `bootstrap`（首屏"没有找到密库"的提示）打在监听器就绪之前，直接丢失。

**现象很隐蔽**：登录页默认就是可见的，所以看起来一切正常，只是首次运行的提示永远不出现。

修法：`onHost()` 返回 Promise，`send({t:"ready"})` 放到 `.then()` 里。

> WebView2 版没有这个问题，因为 `addEventListener` 是同步注册的。

### 5.2 前端资源被编进二进制

C++ 版改前端只要 `cp` 到 `web/` 目录；Tauri 版**必须重新编译**（增量约 7 秒，可接受）。

### 5.3 窗口默认 `visible: false`

要等前端 `ready` 之后再 `show()`，否则会先闪一个白窗口。

### 5.4 拖放事件挂在 `WindowEvent` 上，不是 `WebviewWindow` 的方法

```rust
// 对：
w.on_window_event(|e| {
    if let tauri::WindowEvent::DragDrop(tauri::DragDropEvent::Drop { paths, .. }) = e { ... }
});
// 错：WebviewWindow 没有 on_drag_drop_event 这个方法
```

而且 Tauri 默认会**拦截系统拖放**，webview 里收不到 HTML5 的 drop 事件——
要么走它的回调拿绝对路径，要么把 `dragDropEnabled` 设为 `false`。

### 5.5 debug 版的 PBKDF2 慢很多

20 万轮在 debug 构建下要几秒（release 快一个数量级）。
写自动化测试时等待时间要按 debug 算，否则会误判成"功能没生效"——
这个坑真踩到了：导入预览其实已经出来，只是断言跑得太早。

## 6. 安全三项（已完成）

这三条不属于"功能"，属于"会丢数据或泄密码"的问题，所以先做。

### 6.1 自动锁定

宿主侧看门狗线程，闲置 5 分钟抹掉密钥、清空模型、回到登录页。

**为什么不在前端算**：窗口最小化时浏览器的定时器会被大幅节流，
"离开一小时回来还是解锁状态"正是最危险的情况。计时必须在宿主侧。

前端只负责上报"人还在动"（鼠标/键盘/滚轮），节流 15 秒一次；
收到任何 IPC 消息也会刷新计时。

锁定时**故意不动窗口**——闲置锁定多半发生在用户已经跑去干别的事，
这时把窗口弹到最前面是打扰。用户回来点开，看到的就是登录页。

> 测试用 `SECBACK_IDLE_SECS` 可以缩短这个时长，正常启动不存在。

### 6.2 单实例

第二个实例立即退出，并把已有窗口提上来。

不是体验问题：两个进程各持一份内存模型，交替保存会**把对方的改动静默覆盖掉**。

### 6.3 删除确认

前端弹层，显示要删的项目名，**焦点默认在"取消"**上——防止回车惯性把项目删掉。
确认按钮做成实心红，和普通按钮区分开。

### 6.4 做的时候发现的一个隐患

锁定时如果编辑弹层还开着，它会盖在登录页上，而**里面还留着刚取出来的明文密码**。

已修：`loggedOut` 时关闭所有弹层并清空 `m-slots` / 输入框内容，同时清掉编辑用的 reveal 缓存。

### 7.1 跨机器导入

三步，和 C++ 版一致：

1. **预检**：只读文件头 64 字节，**不需要口令**。分得出"不是密库 / 太短 / 头损坏 /
   版本更新（报出具体版本号）/ 版本过旧"。用户不会输了密码才发现读不了。
2. **输对方密码**：解密后算合并计划。这是**对方机器**的密码，不是本机的。
3. **预览勾选**：树形，项目一行、账户一行，各自可勾。默认合并同名项目；
   已存在的账户标"已存在，不会重复添加"。

**幂等**：同一个文件反复导入，第二次起零变化。靠副本身份由
`(对方项目 id, 组号)` 确定性派生（FNV-1a），不是随机生成。
`core/src/merge.rs` 的 `merge_is_idempotent` 专门盯这条。

**写盘顺序**：先 `write_out` 成功，再换内存。任何一步失败，磁盘和内存都还是原样。

### 7.2 前端始终不碰密码

导入预览里每个账户只有 `hasPass: true/false`，没有明文。
密码只在宿主内部从 A 密库解出来、再加密进 B 密库，中间不经过网页。

### 7.3 修改主密码

换新 salt + 新口令，整库重新加密。旧口令先验证一遍。

验证结果：改完之后 **C++ 版用旧密码读会报 `load failed`**，
说明是真的重新加密，不是只改了某个标记。

### 7.4 密库位置

按这个顺序决定：

1. 环境变量 `SECBACK_VAULT`（测试/调试用，正常启动不存在）
2. exe 同目录的 `secback.cfg` 里的 `vault = ...`
3. 都没有 → exe 同目录的 `sec.properties`

`vault=` 的规则（与 C++ 版逐条对齐，实现在 `core/src/config.rs`）：

- 绝对路径直接用；**相对路径相对 exe 所在目录**
- 支持 `%环境变量%` 展开，**变量不存在就原样保留**——写错了能一眼看出来
- 父目录不存在会**自动创建**
- 分隔符规范化（`/` → `\`，压掉重复）
- 指向目录 → 报错并**挡住登录**

最后一条是故意的。配置写错时如果安静地退回默认路径，用户会以为打开的是原来那个库，
实际却新建了一个空库——**看起来就像数据丢了**。所以宁可不让进。

> 为什么要留这个机制：密库放固定位置（比如文档目录），以后更新程序、换目录、重装，
> 都不会因为"只换了 exe 没带密库"而从一个空库开始。

### 7.5 深色主题

默认深色，菜单「外观」里可切浅色，选择存在 localStorage 里。

实现方式是**叠加**而不是重写：原浅色规则一条没动，文件末尾追加
`[data-theme="dark"]` 前缀的覆盖块，只改颜色、不碰布局。
特异性天然高于原来的类选择器，不需要 `!important`。

三个容易漏的地方（后来都补了）：

1. **硬编码颜色**：原 CSS 里 40 多处直接写死的色值，只改变量根本管不到，
   必须逐条覆盖（登录卡片、输入框、头像、槽位、toast、导入预览……）。
2. **滚动条**：有自定义 `::-webkit-scrollbar-thumb`，`color-scheme: dark` 盖不住它，
   深色下会留一条白杠。
3. **窗口标题栏**：界面变深了，标题栏还是白的会很割裂。宿主侧用
   `WebviewWindow::set_theme` 同步，前端切换后发一条 `theme_sync` 通知。

配色上刻意避开纯黑 `#000` 配纯白 `#fff`——那个对比度太硬，长时间看反而累眼。
底色用偏蓝的深灰 `#14161a`，正文用略暗的 `#e2e5ea`。

顺带修了个老 bug：`--green` 从来没定义过，但 `.item.imported .avatar` 在用
`var(--green)`，"已导入"标记一直是继承色。

## 9. 怎么构建

```bash
# 核心测试（含与 C++ 的向量对拍）
cd core && cargo test

# 桌面应用
npx tauri build            # release + 安装包
npx tauri build --no-bundle # 只出 exe
```

产物：`src-tauri/target/release/secback.exe`

调试驱动界面：

```bash
# 启动时开 CDP 端口
WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS='--remote-debugging-port=9222' ./secback.exe

# 断言 DOM + 截图
node _cdp.mjs out.png "document.querySelectorAll('.item').length"
```

`SECBACK_VAULT` 环境变量可以指定密库位置（测试用）。
