# 构建与验证

## 环境与版本

Windows 使用 Node.js 24、Rust 1.90 或更新版本、MSVC 和 WebView2。Android 还需 JDK 21、SDK 37、NDK；本轮使用 NDK 29.0.14206865 和 Gradle 9.6.1。本机路径应按安装位置配置，不写入发布源码。

根 package.json 为产品版本入口，当前产品版本为 0.1.1。Tauri 读取 version，Android 的显示版本与之相同。androidVersionCode 是独立且必须递增的安装升级序号；0.1.0 从 1.0.0 调试包过渡时使用 1000001；0.1.1 递增为 1000002，以保留已有密库并允许覆盖升级。以后发布时同步递增该字段，不能随显示版本降低。scripts/check-version.mjs 检查宿主 Cargo、Cargo.lock、npm lockfile 和安装序号；核心库保持独立版本。

## 常规命令

在工程根目录执行：

~~~powershell
npm ci
node scripts/check-version.mjs
node --check src/app.js
cargo test --manifest-path core/Cargo.toml --locked
cargo test --manifest-path src-tauri/Cargo.toml --lib --locked
npx tauri build --debug --no-bundle
~~~

设置 CARGO_TARGET_DIR 可将大缓存放到工程外；此前空间清理后不要无意恢复多套 target。core 的 peek 工具仅在显式 --features dev-tools 时可编译，会输出明文，不随产品交付或连接真实密库。

## Windows 交付

执行 `npm run build:windows`（或 `node scripts/build-windows.mjs`），自动校验版本、构建 release，并复制为 `delivery/SecBack-<version>-Windows-x64.exe`。`--debug` 可生成带 `-debug` 后缀的调试成品。正式交付统一使用此脚本，避免手工复制时遗漏版本号；Cargo 内部的 secback.exe 仍为编译中间产物。

## Android 发布

先配置 ANDROID_HOME、NDK_HOME、JAVA_HOME、PATH，再执行：

~~~powershell
node scripts/build-android.mjs
~~~

签名使用被忽略的 keystore/secback-release.keystore 和 signing.properties，后者只含 storePassword、keyAlias、keyPassword；也可用同名 SECBACK_ 大写环境变量。证书指纹必须与既有安装一致。不要在终端输出密码或提交签名配置。

脚本严格按原生编译 → .so 复制 → Gradle → verify-release.ps1 → delivery 的顺序执行；仅在确认 native release 完成且错误为 Windows 符号链接限制时启用复制兜底。其他失败会中止。

输出为 `delivery/android/SecBack-<version>-Android-arm64.apk` 及 `.apk.manifest.json`。版本号自动读取 package.json；也可用 `npm run build:android` 调用。校验包内 arm64 原生库与本次编译逐字节 SHA-256 一致、无其他 ABI、发布签名、包名/版本/versionCode、非 debuggable 标记。校验脚本也可单独执行，必填 -Apk 和 -Native。Gradle 内部的 app-arm64-release.apk 不作为最终文件名。

可选本地环境：
- SECBACK_ANDROID_PROJECT：隔离 Android 工程绝对路径，须先同步手工 Kotlin、Manifest、res 和 Gradle 源码；签名及版本仍取当前源码根。
- GRADLE_USER_HOME：独立 Gradle 缓存。
- SECBACK_GRADLE_BIN：自定义 Gradle 可执行文件。
- SECBACK_GRADLE_OFFLINE=1：缓存齐全时离线打包。
- SECBACK_GRADLE_INIT：Gradle init 脚本路径。本机 Java 编译权限问题可在 init 脚本中令 JavaCompile.options.fork=true，并指定 JDK21 的 javac；这是本地规避，不进产品配置。

隔离工程的自定义源码须同步，不能仅复制 .so 后用旧 Kotlin 壳打包。

## 桌面 WebView 回归

移动滚动与排序回归另执行 `tests/mobile-scroll-ui.mjs`：通过 CDP 触摸事件持续拖到首尾，验证滚动边界、列表及详情底栏、密码图标与后台遮盖。等待弹层动画完成后再测量按钮，避免把动画缩放误判为触摸尺寸不足。2026-11-26 修复与交付见 `Android滚动与密码框修复-2026-11-26.md`。

用独立虚构密库启动调试 exe，设置 SECBACK_VAULT、WEBVIEW2_USER_DATA_FOLDER 和 WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=--remote-debugging-port=9223。测试设置 CDP_PORT=9223 后按顺序执行 tests/p1-ui.mjs、tests/p2-ui.mjs。二者临时截获前端 send，只验证界面/消息生成；不等于真实宿主回归。

tests/p2-host.mjs 需额外指定 SECBACK_TEST_VAULT 和 SECBACK_TEST_PASSWORD，仅连接可丢弃的测试密库。它核对实际宿主路径，覆盖非法请求、状态门禁、保存失败/重试、锁定清理与冷却，确实会修改虚构库。

tests/p2-perf-ui.mjs 临时生成 100/1000/10000 条虚构列表，记录 JS/DOM 同步耗时；core/examples/perf.rs 记录 Rust 保存/解锁/合并和分配峰值。两者均不是手机端总体性能指标。

CDP、绕过 WebView 沙箱等本地测试参数不得写进发布配置。测试完成停止仅属于本次验证的进程。

## 增量和手机验收

只改 src 文件、不修改 Rust 时间戳，分别重新构建桌面与 Android。检查 UI revision、编译触发、原生库哈希及 APK 内库一致性；详见本轮验证记录。

每批 ADB 操作先连接设备。覆盖安装后确认密库项目仍在，检查真实复制、后台再回前台需登录、深浅主题、系统栏、键盘与滚动时顶部操作栏、导出取消及回读成功。不可用黑截图判断 WebView 是否崩溃。

## Android 外部库与漏洞审计

导入通过 dialog 返回 FilePath，再由 fs 插件打开 content URI；读取密文最多 64 MiB + 272 字节。预检与密码验证使用同一份内存快照。系统文件选择器期间抑制后台锁定，闲置锁定仍有效；结果回调校验登录会话及导入请求序号，锁定、取消或更新请求后丢弃过期结果。取消、锁定、完成后释放导入状态，无明文临时文件。

生成可丢弃的 v1/v2/冲突测试库：设置 SECBACK_FIXTURE_DIR 为已存在的测试目录后运行核心测试；输出只含固定虚构数据。桌面 tests/import-host.mjs 需要 SECBACK_TEST_VAULT、SECBACK_TEST_PASSWORD、SECBACK_IMPORT_FIXTURE 和 CDP_PORT，先核对宿主路径再执行错误密码、预览取消、确认及重登录持久化测试。

CI 包含 Windows/Linux 核心测试、Windows 宿主测试和 debug 构建、Android arm64 debug 构建、npm audit、两个 Cargo.lock 的 cargo-audit，以及 Gradle 应用/测试/插件/buildSrc 解析图的 OSV Maven 审计。Android debug 使用临时调试签名，不读取发布私钥。Gradle 非敏感 properties 与 wrapper 配置须纳入版本控制，wrapper 下载校验官方 SHA-256。CI 初始化已在独立源码副本验证保留手工 Activity 和 Gradle 配置。

本地 Gradle 审计示例（先设置 JDK/SDK，再在 Android 工程执行；路径请替换）：

~~~powershell
./gradlew --no-daemon --no-configuration-cache -I <源码根>/scripts/audit-gradle.init.gradle -Psecback.auditOutput=<绝对路径>/gradle-coordinates.json :secbackAuditCoordinates
./gradlew -p buildSrc --no-daemon --no-configuration-cache -I <源码根>/scripts/audit-gradle.init.gradle -Psecback.auditOutput=<绝对路径>/buildsrc-coordinates.json :secbackAuditCoordinates
node <源码根>/scripts/audit-gradle.mjs <绝对路径>/gradle-coordinates.json <绝对路径>/gradle-audit.json <绝对路径>/buildsrc-coordinates.json
~~~

审计解析或网络查询失败即非零退出，发现未撤回漏洞也非零退出，不用忽略项掩盖结果。OSV 查询上传公开依赖坐标和版本，不读取密库或签名材料。报告必须区分应用运行依赖与构建工具链；当前构建工具尚有命中，详见后续审计报告。远端 GitHub Actions 未执行时，不能把本机检查写成远端 CI 已通过。

## 图标与桌面菜单

`src/assets/app-icon.svg` 为默认图标源；Android 前景、背景、单色源及生成配置在 `src-tauri/icons/`。执行 `npm run icons:generate` 可重新生成多尺寸 ICO、PNG 和 Android 自适应图标。`build.rs` 跟踪图标变动；Android 交付脚本在使用隔离 Gradle 工程时会同步权威工程的资源，避免打包旧图标。

Windows 保留原生标题栏，文件／外观／帮助使用主题菜单，支持 F10、Alt+F/V/H、方向键、Home/End、Esc 以及原有操作快捷键。详情正文独立滚动，标题与底部操作栏固定。`tests/polish-ui.mjs` 使用 CDP 检查滚轮边界、菜单导航、锁库禁用及导入操作；Android 真机验证须另行完成。
